# Where the framework broke when run on itself (2026-11-07 → 08)

Self-run: I acted as the main prism; four rays (components · method · native Claude · external stack) ran as sub-prisms; then three skeptic workflows (66 agents) verified the rays. Each break below became a rule in `FRAMEWORK.md`.

| # | What broke | Evidence | Rule it produced |
|---|---|---|---|
| 1 | **The main prism accepted its sub-prisms' output without verification.** The first pass of the design (7 fixed "bands", then a 4-part unit) was presented as settled. | You caught it: "you just kept accepting whatever I say without research." Skeptics then refuted part of 6 of the 9 claims they managed to test (C1, C2, C3, M1, M2, M3). | Critic proposes, **code gates decide**; an LLM's own check is not completeness (Huang 2023, Kamoi 2024). §6 |
| 2 | **No budget partition.** Three workflows (66 agents) launched in parallel; the session limit hit and **41 verifiers died**, including every verifier for the stop rule (M5) and the deliverable format (D1). | Workflow results: A 12/29 done, B 11/32, C 2/5. | Budget inherits by **partition**, Σ(children) ≤ cap, checked at merge; verification ordered by priority (must-claims first); saturation instead of "run everything". This is exactly the C3 refutation, reproduced live. §2, §5 |
| 3 | **Goal-only downward split lost a decision.** The rays never knew the intended deliverable form (one file vs bundle), so the question surfaced last, from Ray 3, and could not be resolved before the limit. | D1 appeared after three rays had finished. The C1 design lens found the same pattern in the Apollo walkthrough (a trigger choice made three levels down could not call a local script). | **Decision inputs are resolved at intake**, ≤3 questions with defaults; the environment profile flows down as a Constraint. §2 Inputs, §4 |

What worked: decomposition into independent rays; forcing every claim through three *different* lenses (evidence / design / counterexample) found failures that a single reviewer would not (the design-walkthrough lens produced most refutations); writing the build pack in the proposed task.md layout exposed missing columns immediately.

Verified on 2026-11-08 in two priority batches after the limit reset: D1 (1/3 refuted; all lenses converged on one `task.md` with embedded bootstrap blocks), M2 (1/3), M3 (3/3 — replaced), M4 (1/3), M5 (2/3 — replaced), M6 (1/3); all folded into `FRAMEWORK.md` §3, §5, §6, §9.
